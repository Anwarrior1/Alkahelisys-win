# مركز الكحيلي لغسيل السيارات

نظام ERP محلي لإدارة مركز غسيل السيارات، بواجهة عربية RTL كاملة، ولوحة تشغيل للموظف ولوحة مالية وإدارية محمية للمدير.

## التشغيل السريع

المتطلبات للتطوير فقط: Node.js 20–24 وRust المستقر. نسخة Windows المثبتة لا تحتاج إلى Node.js أو Rust أو خادم قواعد بيانات، كما يتضمن مثبتها WebView2 Offline Installer عند الحاجة.

```bash
npm install
npm run dev
```

ثم افتح `http://localhost:1420`. عند أول تشغيل، ينشئ النظام حساب المدير الأول من شاشة آمنة؛ لا توجد كلمة مرور افتراضية مضمنة في المشروع.

لتشغيل نافذة سطح المكتب أثناء التطوير:

```bash
npm run desktop:dev
```

لا تشغّل `npm run dev` في طرفية أخرى بالتزامن مع أمر Tauri؛ أمر Tauri يبدأ الخدمة والواجهة تلقائيًا.

## بناء Windows

نفّذ البناء على جهاز Windows x64 أو اترك GitHub Actions ينفذه على `windows-latest`:

```bash
npm ci
npm run lint
npm run test:api
npm run dist:win
```

يبني الأمر حزمة NSIS x64 ثم ينسخها إلى اسم ثابت:

```text
release/Alkahelisys-Windows-x64-Setup.exe
```

يبقى `npm run build` متاحًا على Windows لبناء NSIS وMSI معًا. يحمل التطبيق الاسم والهوية **مركز الكحيلي لغسيل السيارات** (`ly.alkaheli.carwash`) ويُثبت للمستخدم الحالي مع اختصاري سطح المكتب وقائمة Start وإلغاء تثبيت نظيف.

عند تشغيل نسخة سطح المكتب، يبدأ خادم Axum الداخلي تلقائيًا داخل عملية التطبيق نفسها على loopback؛ لا تظهر نافذة طرفية ولا يلزم تشغيل خدمة يدويًا. تحجز عملية Tauri منفذ الخدمة قبل فتح الواجهة لتجنب سباق بدء التشغيل، وتنتهي الخدمة تلقائيًا عند إغلاق التطبيق.

## البيانات المحلية والنسخ الاحتياطي

- لا تستخدم السجلات التجارية LocalStorage؛ جميعها محفوظة في SQLite.
- في نسخة Windows المكتبية تحفظ البيانات في مسار AppData المحلي للمستخدم، عادةً قريب من:

  ```text
  C:\Users\<المستخدم>\AppData\Local\ly.alkaheli.carwash\AlkaheliCarWashERP\carwash.db
  ```

- تستخدم القاعدة WAL، و`foreign_keys=ON` و`busy_timeout`.
- لا تُحزم قاعدة التشغيل داخل موارد التطبيق ولا داخل مجلد التثبيت. يفتح `Database::open` الملف الموجود نفسه، وينشئه ويشغّل migrations وبيانات النظام المطلوبة فقط عندما لا توجد قاعدة بعد. تستخدم كل بيانات النظام المبدئية `INSERT OR IGNORE` ولا تمسح قاعدة موجودة.
- الصور المرفوعة ونسخ النظام الاحتياطية وملفات الاستعادة المرحلية تحفظ تحت مجلد `AlkaheliCarWashERP` نفسه. الملفات التي يختار المدير تصديرها تحفظ في المسار الذي يختاره عبر نافذة Windows.
- ينشئ المدير النسخ الاحتياطية من داخل التطبيق عبر نسخة SQLite متسقة (`VACUUM INTO`). في نسخة سطح المكتب يمكن اختيار موقع الحفظ من نافذة النظام.
- تتحقق الاستعادة من `PRAGMA integrity_check` قبل الاستبدال، وتنشئ نسخة طوارئ قبلها وتبطل الجلسات بعد نجاحها.

لا يحذف NSIS بيانات AppData عند التحديث أو إلغاء تثبيت ملفات البرنامج، ولذلك تبقى قاعدة SQLite خارج دورة حياة ملفات `Program Files` وموارد Tauri.

## GitHub Actions والإصدارات

يشغّل الملف `.github/workflows/windows-build.yml` الفحص والاختبارات وبناء NSIS على كل push إلى `main`، ويرفع المثبت كـ Actions artifact. عند دفع tag مطابق لنسخة `package.json` مثل `v1.0.0`، ينشئ أو يحدّث GitHub Release ويرفق الملف:

```text
Alkahelisys-Windows-x64-Setup.exe
```

لإنشاء إصدار 1.0.0 بعد دفع `main`:

```bash
git tag v1.0.0
git push origin v1.0.0
```

## الأمان والصلاحيات

- كلمات المرور مجزأة بخوارزمية Argon2id؛ لا تُحفظ كنص صريح.
- الجلسات رموز عشوائية تُخزَّن تجزئتها فقط.
- كل مسار مالي يفرض دور `manager` على الخادم، وليس في الواجهة فقط.
- مسارات الموظف التشغيلية تستخدم DTOs منفصلة ولا تعيد العمولة أو الأرباح أو الأرصدة أو المصروفات أو بيانات المدفوعات.
- الأسعار تعامل بوحدة 1/1000 من الدينار (`INTEGER`) والنسب بنقاط أساس (`5000 = 50%`)؛ لا تستخدم الحسابات المالية `float`.

## قواعد الحساب الأساسية

```text
عمولة العامل = تقريب نصف لأعلى(سعر الغسلة × نسبة العمولة المثبتة)
حصة الأعمال = سعر الغسلة − عمولة العامل
صافي ربح الأعمال = حصة الأعمال − حصة الأعمال من المصروفات فقط
```

تُسجَّل الغسلة مرة واحدة فقط. داخل معاملة SQLite واحدة ينشئ النظام الغسلة وسجل العامل والعمولة وحصة الأعمال وديون المعرض (عند الحاجة) والقيود المالية وسجل التدقيق. تغيير نسبة العمولة لاحقًا يؤثر في الغسلات الجديدة فقط.

## الاختبارات

```bash
npm run test:api
npm run build:web
```

تشمل اختبارات API: إعداد المدير وتسجيل الدخول، عمولة 50%، حجب بيانات المدير من الموظف حتى عبر المسارات المباشرة، ومنع حقول العمولة من DTOs التشغيلية، وتوزيع المصروف المشترك بالتساوي مع سجل قابل للتدقيق.

## البنية

```text
React + TypeScript + Vite       واجهة عربية موحدة
Axum + Rust                     خدمة محلية وقواعد أعمال مشتركة
SQLite (rusqlite)               قاعدة بيانات دائمة محلية
Tauri 2                         نافذة سطح مكتب وحزم Windows
```

الخدمة نفسها تعمل على `127.0.0.1:8787` للتطوير وعلى loopback داخل نافذة Tauri؛ لذلك لا توجد قواعد أعمال منفصلة للويب وسطح المكتب.
